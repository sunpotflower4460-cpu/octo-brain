## 0. 本番の初回実測(2026-09-30・件数が少ないので参考値)

本番 Worker の原価ログ(`cost:*`)。原価ログの単価は models.ts のピーク時単価なので、オフピークはこの約半分になる。

| 種別 | 件数 | 1回あたりの概算原価 | 所要時間 |
|---|---|---|---|
| light(4腕+統合+検証、7コール) | 5 | 約 $0.0052〜0.0059(約0.8〜0.9円) | 11〜13秒 |
| deep(8腕+統合+検証、11コール) | 1 | 約 $0.0069(約1.0円) | 12.6秒 |
| 深化(5コール) | 2 | 約 $0.0036(約0.5円) | 9〜10秒 |
| 中断(統合前で停止) | 2 | 約 $0.001 | — |

- 原価の約7割は統合脳(deepseek-v4-pro)。ノードは flash なので 8 腕にしても増えるのは約 +30%
- 無料枠 100 単位を使い切るユーザー1人の月間原価は約 $0.5〜0.6(約80〜90円)

### モデル構成ごとの原価比較(上の実測トークン数に各社の公式単価を当てた試算)

平均トークン数(light 1回): ルーター 112/1、ノード 204/139 ×4、統合 1425/633、検証 550/72(入力/出力)

| 構成 | light 1回 | 深化 1回 | 備考 |
|---|---|---|---|
| DeepSeek(ピーク) | 約0.86円 | 約0.54円 | 現行の既定 |
| DeepSeek(オフピーク) | 約0.43円 | 約0.27円 | 時間帯で半額 |
| **全部 GPT-6 Luna(推論オフ)** | **約0.15円** | **約0.10円** | `OPENAI_API_KEY` を登録すると自動で切り替わる |
| Luna + 統合だけ DeepSeek Pro | 約0.74円 | 約0.45円 | 統合の質を優先する場合 |
| Luna + 統合だけ GPT-6 Sol | 約1.45円 | 約0.87円 | 最上位の統合 |

- GPT-6 Luna は推論モデルで、既定の推論は medium。推論トークンは出力として課金されるので、必ず `reasoning_effort: "none"`(models.ts で設定済み)
- **推論ありで使う場合**: `LUNA_SYNTH_REASONING = "low" | "medium" | "high"` で統合脳だけ推論をオンにできる。
  推論トークン数は未実測。仮に統合1回で 1,000〜4,000 トークン考えると、出力単価 $0.50 で **+約0.08〜0.3円/回**
  (Luna 全部で約0.23〜0.45円/回)。DeepSeek(ピーク)の約0.86円よりまだ安い。待ち時間は数秒〜十数秒延びる
- 8本のノードまで推論をオンにすると、並列8本分の推論トークンと待ち時間が乗るので非推奨(狭い作業なので効果も小さい)
- 日本語のトークン化はモデルごとに違うので、切り替えたら `npm run ops:report` で実測し直す
- 品質は未比較。切り替えたら `npm run bench` で多角性と深さを確認する

### 課金なし(完全無料)運用の原価の天井

| 仕組み | 既定値 | 役割 |
|---|---|---|
| 全体の1日予算 `DAILY_BUDGET_USD` | $3/日(月約$90) | 超えたらその日は 503 で受付を止める(UTC 0時に復帰) |
| 1人の月間無料枠 `FREE_MONTHLY_QUOTA` | 100単位 | ディープ・深掘りは2単位 |
| 同一IPの1日上限 `IP_DAILY_QUOTA` | 300単位 | clientId の使い捨て対策 |
| IP のバースト制限 | 20回/60秒 | 連打・スクリプト対策 |

- 1日 $3 で受けられる回数は、DeepSeek(ピーク)で約520回/日、**Luna で約3,000回/日**
- 固定費は Workers Paid の $5/月(KV の書き込み上限のため推奨)

## 1. 1回答あたりの実コスト(原価)

OctoBrain の1回答は次のモデル呼び出しの合計:

```
コスト/回 = router + Σ(node × 起動腕数) + synth + verify
          = Σ_call ( inTok/1e6 × pricePerMTokIn + outTok/1e6 × pricePerMTokOut )
```

- 単価は `workers/src/config/models.ts`(唯一の正)。**ドキュメントに価格を書かない**(絶対ルール2)
- 実測は原価ログから: `npm run ops:report -- --days 7`(総コスト・件数・平均ms・内訳)
- プラン別の腕数(`docs/01_depth_design.md §6`):
  - **light**(無料想定): 2軸4腕 + Flash統合 → 概算 `<実測>` 円/回
  - **deep**(Pro想定): 4軸8腕 + Pro統合 → 概算 `<実測>` 円/回
- **キャッシュヒット率**: DeepSeek の `prompt_cache_hit_tokens` を実測し、見積り(0.4〜0.75円/回)を置き換える → `<実測>`

## 2. 深化・共鳴の追加原価(プレミアム根拠)

- 深化 = 4コール(対角2腕の再取得 + 再考2 + 中央織り直し)/ 共鳴 = 1コール
- `ops:report` の内訳(`kind: deepen / resonate`)で **使用率と追加コスト**を実測 → `<実測>`
- プレミアム(Pro)の象徴機能。サブスク下限の妥当性の根拠にする

## 3. 損益分岐と価格の考え方(枠組み)

- **無料枠**: 月 N 回 × light 原価 = 1ユーザーあたり月間原価上限。N は `FREE_MONTHLY_QUOTA`(現状100)
  - 無料の損益分岐: `月間インフラ許容額 / (light原価 × 想定アクティブ率)` → `<実測>`
- **Pro(月額)**: deep + 深化/共鳴 + 回数増。Apple 手数料(15〜30%)後で採算が出る下限を置く
  - 方針は「**サブスク下限は安く**」。ただし 480円台は手数料後ギリギリ → 深化/共鳴の実使用率(P4実測)を見て最終決定
- **リワード動画広告(非強制・補助)**: eCPM 実測まで収益は控えめに見積もる。青天井にせずサブスクと段差
